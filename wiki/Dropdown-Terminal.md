# Dropdown terminal (TildaZ)

A Quake-style terminal: press **F1**, a terminal slides down over whatever you are doing; press F1 again and it is gone. It is [TildaZ](https://github.com/ensky0/tildaz) by ensky0 ([tildaz.dev](https://tildaz.dev)), a native Wayland dropdown terminal.

In i3 you probably did this with the scratchpad (`for_window [class="dropdown"] move scratchpad` plus `bindsym F1 [class="dropdown"] scratchpad show`). TildaZ does the whole job by itself: it owns its hotkey, size, position and hide/show.

(An older version of this setup used Kitty on a Hyprland special workspace. That is gone; TildaZ replaced it.)

## The pieces

| Piece | Repo | Live | Role |
|-------|------|------|------|
| TildaZ config | `tildaz/config_0.toml` | `~/.config/tildaz/config_0.toml` | Hotkey (F1), size, dock edge, opacity, font, theme, shell, keys |
| Extra toggle keys | `hypr/bindings.lua` | `~/.config/hypr/bindings.lua` | Favorites key, KP Delete, mouse forward → `tildaz --toggle` |
| Autostart | not in repo | `~/.config/hypr/tildaz.lua` | Written by `tildaz --desktop add` |
| Loader | `hypr/hyprland.lua` | `~/.config/hypr/hyprland.lua` | Last line: `pcall(require, "tildaz")` |
| Blur + slide | `hypr/looknfeel.lua` | `~/.config/hypr/looknfeel.lua` | `hl.layer_rule` for namespace `tildaz` |

## Install

`./install.sh` does all of this for you unless you pass `--skip-tildaz`: it copies `tildaz/config_0.toml` first (so the first run already uses F1 and these sizes), runs the official installer, then runs `tildaz --desktop add`.

By hand:

```bash
# Official installer: user-local, no sudo, checks the SHA-256
curl -LsSf https://tildaz.dev/install.sh | sh
```

It installs to `~/.local/share/tildaz`, links `~/.local/bin/tildaz`, adds an app-menu entry and starts TildaZ once. To update, quit TildaZ and run the same command again (your config is kept). To uninstall: `curl -LsSf https://tildaz.dev/uninstall.sh | sh`.

Then copy the config and register it with Hyprland:

```bash
mkdir -p ~/.config/tildaz
cp tildaz/config_0.toml ~/.config/tildaz/config_0.toml
tildaz --desktop add
```

## Autostart

`tildaz --desktop add` writes `~/.config/hypr/tildaz.lua`. On this machine it looks like this:

```lua
-- Written by "tildaz --desktop add". "tildaz --desktop remove" deletes this file.
hl.on("hyprland.start", function() hl.exec_cmd("/home/mahmoud/.local/share/tildaz/tildaz --autostart") end)
-- The autogenerated-config warning bar covers the top of the screen, where TildaZ opens.
hl.config({ autogenerated = false })
```

The file holds a path for the local user, so it is **not** in the repo. Each machine generates its own. `hyprland.lua` loads it on its last line:

```lua
pcall(require, "tildaz")
```

`pcall` means a machine without TildaZ just skips it. `tildaz --desktop remove` deletes the file and undoes the setup.

`auto_start = true` in `config_0.toml` also makes TildaZ keep an XDG autostart entry (`~/.config/autostart/tildaz.desktop`).

## The keys

| Key | Where it is set | What it does |
|-----|-----------------|--------------|
| **F1** | `hotkey` in `config_0.toml` | TildaZ registers it with Hyprland itself |
| XF86Favorites | `bindings.lua` | `tildaz --toggle` |
| KP Delete (`code:91`) | `bindings.lua` | `tildaz --toggle` |
| Mouse forward (`mouse:276`) | `bindings.lua` | `tildaz --toggle` |

The extra binds in `bindings.lua`:

```lua
o.bind("XF86Favorites", "Dropdown terminal", { launch = "tildaz --toggle" })
o.bind("code:91", "Dropdown terminal", { launch = "tildaz --toggle" }) -- KP Delete
o.bind("mouse:276", "Dropdown terminal", { launch = "tildaz --toggle" })
```

`tildaz --toggle` shows or hides the running instance, and starts it if it is not running. Do not add `{ mouse = true }` to the mouse bind: that flag is for drag and resize binds, and a click command with it never runs.

### Keep the hotkey on an F-key

Hyprland matches TildaZ's hotkey by the **character** the active layout types. This setup switches between US and Arabic (Win+Space). A letter hotkey such as `ctrl+t` stops working while Arabic is active, because the Arabic layout does not type Latin letters. F1–F12 are the same on every layout, so they always work. TildaZ's own [CONFIG.md](https://github.com/ensky0/tildaz/blob/main/CONFIG.md) has a table of which layouts break which keys.

The shortcuts *inside* TildaZ (the `[keys]` table) are not affected. They work on every layout.

## Settings (`config_0.toml`)

TildaZ's full reference is [CONFIG.md](https://github.com/ensky0/tildaz/blob/main/CONFIG.md). What this repo sets:

| Key | Value here | Notes |
|-----|------------|-------|
| `hotkey` | `"F1"` | A key with no modifier must be F1–F12. `Shift` alone is not a valid modifier |
| `shell` | `"/usr/bin/bash"` | Absolute path, no arguments on Linux |
| `auto_start` | `true` | Start on login |
| `hidden_start` | `false` | `true` = start hidden, first toggle shows it |
| `theme` | `"Tilda"` | Built-in themes include `Ghostty`, `Catppuccin Mocha`, `Dracula`, `Gruvbox Dark`, `Tokyo Night`, `Nord`, `Rosé Pine`, `Kanagawa`, `Everforest Dark`, and light ones |
| `max_scroll_lines` | `10000` | Scrollback |
| `window.dock_position` | `"top"` | `top`, `bottom`, `left` or `right` |
| `window.width_percent` | `95.0` | % of the screen |
| `window.height_percent` | `50.0` | % of the screen |
| `window.offset_percent` | `50.0` | Position along the edge: 0 = start, 50 = centre, 100 = end |
| `window.opacity_percent` | `90.0` | 90% opaque; the layer rule blurs what shows through |
| `font.family` | `"DejaVu Sans Mono"` | Falls back to the system monospace font if missing |
| `font.glyph_fallback` | `["Noto Sans CJK KR", "Noto Color Emoji"]` | Up to 7 entries |
| `font.size_point` | `15` | 8–72 |
| `font.line_height_ratio` | `1.1` | |

Values outside the allowed range are clamped. A value TildaZ cannot read falls back to its default, and TildaZ tells you which field it replaced.

### Keys inside TildaZ (`[keys]`)

Each action takes a list of keys; `[]` unbinds it.

| Group | Keys in this config |
|-------|---------------------|
| Tabs | `ctrl+shift+t` new, `ctrl+shift+w` close, `ctrl+shift+[` / `ctrl+shift+]` previous / next, `alt+1`…`alt+9` go to tab |
| Panes | `ctrl+shift+arrows` split, `alt+arrows` focus, `shift+alt+arrows` resize, `shift+alt+0` equalize, `ctrl+shift+z` zoom, `ctrl+shift+x` close |
| Search | `ctrl+shift+f` |
| Clipboard | `ctrl+shift+c` copy, `ctrl+shift+v` paste |
| Window | `alt+return` fullscreen, `shift+alt+return` fill the work area, `alt+f4` quit |
| Font size | `ctrl+shift+=` / `ctrl+shift+plus` bigger, `ctrl+shift+-` smaller, `ctrl+shift+backspace` reset |
| Tools | `ctrl+shift+r` reset terminal, `ctrl+shift+i` about, `ctrl+shift+p` open config, `ctrl+shift+l` open log, `ctrl+shift+/` shortcut list |

Note: in i3 muscle memory, `alt+arrows` and `ctrl+shift+arrows` are now TildaZ pane keys while TildaZ has focus. Hyprland's Super binds are not affected.

### Applying changes

Edit `~/.config/tildaz/config_0.toml` (or press `ctrl+shift+p` inside TildaZ to open it). Then quit TildaZ (`alt+f4`) and run `tildaz --toggle` (or press the Favorites key), which starts it again with the new settings. TildaZ registers its hotkey when it starts, so a changed `hotkey` takes effect after this restart. Copy the file back to `tildaz/config_0.toml` in the repo if you want to keep the change.

The log is at `~/.local/state/tildaz/tildaz_0.log`.

## Why window rules do not work on it

TildaZ is not a normal window. It is a Wayland **layer surface** (the same kind of thing as the bar), with the namespace `tildaz`. So:

- `o.window(...)` / `hl.window_rule(...)` never match it.
- `hyprctl clients` does not list it. `hyprctl layers` does, while it is shown.
- Its size and position come from `config_0.toml`, not from Hyprland.
- Blur and animation come from a **layer rule**.

The layer rule in `hypr/looknfeel.lua`:

```lua
hl.layer_rule({
  match = { namespace = "tildaz" },
  blur = true,
  ignore_alpha = 0.1,
  animation = "slide top",
})
```

| Field | Effect |
|-------|--------|
| `blur = true` | Blur the windows behind the 90% opaque terminal |
| `ignore_alpha = 0.1` | Do not blur pixels that are almost fully transparent (under 10% alpha) |
| `animation = "slide top"` | Slide in from the top edge |

### Change the animation

Swap the `animation` string, then reload:

| Value | Effect |
|-------|--------|
| `"slide top"` | Slide down from the top (shipped) |
| `"slide bottom"` | Slide up from the bottom (use with `dock_position = "bottom"`) |
| `"fade"` | Fade in and out |
| `"popin"` | Grow from the centre |

Match the slide direction to `dock_position`, or it will slide in from the wrong edge. To turn blur off, set `blur = false`.

```bash
hyprctl reload && hyprctl configerrors
```

## Check that it works

```bash
pgrep -a tildaz                  # is it running?
hyprctl binds | grep -i tildaz   # F1 (registered by TildaZ) and the three extra binds
# press F1, then while it is shown:
hyprctl layers | grep tildaz     # namespace: tildaz
```

If `hyprctl layers` shows nothing, TildaZ is hidden. Show it first; a hidden layer surface is not listed.

## Common problems

| Problem | Fix |
|---------|-----|
| F1 does nothing after login | `pgrep -a tildaz`. If it is not running, check `~/.config/hypr/tildaz.lua` exists (run `tildaz --desktop add`) |
| F1 works, the Favorites key does not | `wev` to check the key name; the bind needs hy3 loaded, because it sits after the `hy3 == nil` return in `bindings.lua` |
| Hotkey dead only in Arabic | Your `hotkey` is a letter. Use an F-key |
| Mouse forward does nothing | `wev` → hold the button over a window; you want `mouse:276`. No `{ mouse = true }` on the bind |
| No blur | `decoration.blur.enabled` must be `true` (it is, in `looknfeel.lua`) and the layer rule must match `tildaz` |
| A warning bar covers the top of the screen | That is Hyprland's "autogenerated config" bar; `tildaz.lua` turns it off with `hl.config({ autogenerated = false })` |
