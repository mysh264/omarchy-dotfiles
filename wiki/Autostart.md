# Autostart (`autostart.lua`)

**Repo:** `hypr/autostart.lua`  
**Live:** `~/.config/hypr/autostart.lua`

Programs that start **once at login**. A plain `hyprctl reload` does not run them again. In i3 these were your `exec` lines (not `exec_always`).

Omarchy's own startups (the shell/bar, first-run setup, udiskie, monitor watcher and more) live in `/usr/share/omarchy/default/hypr/autostart.lua` and run before yours. Keep this file for your extras only.

## What ships

```lua
-- hy3 deadlocks NVIDIA renderer startup on this laptop, so it is not loaded
-- from hyprland.lua. Load it once Hyprland is up, then re-read the config so
-- the hy3 layout and keybindings apply. hyprland.start does not fire on reload.
o.exec_on_start("hyprpm reload && hyprctl reload")

-- Lean Conky Config. start-lcc.sh waits 3 seconds, kills a previous copy
-- started by this script, and installs its font. This runs on login only.
o.exec_on_start((os.getenv("HOME") or "") .. "/.config/conky/start-lcc.sh")

-- TildaZ (dropdown terminal) starts itself from hypr/tildaz.lua, which
-- "tildaz --desktop add" writes and hyprland.lua loads.
```

### 1. Load hy3 late

**Why:** loading hy3 during a cold start deadlocks the NVIDIA renderer on this laptop: black screen, login times out.

**What happens:** the first config pass runs without hy3. The layout is `dwindle` and `bindings.lua` stops before the hy3 binds. Then `hyprpm reload` loads the plugin and `hyprctl reload` runs every config file again, this time with hy3: the layout becomes `hy3` and the i3 keys apply.

Do not move this into an early plugin load in `hyprland.lua` unless you have tested it on your GPU.

### 2. Conky

Expects [lean-conky-config](https://github.com/mysh264/lean-conky-config) in `~/.config/conky/` (`./install.sh --with-conky` clones it). If the script is missing the command just fails quietly. Remove the line if you do not use Conky. See [Conky](Conky).

### 3. TildaZ (not in this file)

The dropdown terminal is started by `~/.config/hypr/tildaz.lua`, which `tildaz --desktop add` writes:

```lua
-- Written by "tildaz --desktop add". "tildaz --desktop remove" deletes this file.
hl.on("hyprland.start", function() hl.exec_cmd("/home/mahmoud/.local/share/tildaz/tildaz --autostart") end)
-- The autogenerated-config warning bar covers the top of the screen, where TildaZ opens.
hl.config({ autogenerated = false })
```

It holds a path for the local user, so it is not in the repo. `hyprland.lua` loads it with `pcall(require, "tildaz")` on its last line. See [Dropdown Terminal](Dropdown-Terminal).

## Add your own

| Helper | What it does | i3 |
|--------|--------------|----|
| `o.exec_on_start(cmd)` | Runs a shell command once, on `hyprland.start` | `exec cmd` |
| `o.launch_on_start(cmd)` | Same, but wrapped as `uwsm-app -- cmd` (Omarchy's way to start apps) | `exec cmd` |

```lua
o.exec_on_start("my-daemon --flag")     -- a script or daemon
o.launch_on_start("my-gui-app")         -- a GUI app, started through uwsm
```

There is no direct `exec_always`. Lua in your config files *does* run on every reload, but a command you start from there would start again each time. Use the helpers above for anything that should run once.

Example — night light (see [Night Light and Portal](Night-Light-and-Portal)):

```lua
o.launch_on_start("hyprsunset")
```

## Check it worked

These only run at login, so log out and back in after a change. Then:

```bash
hyprctl plugin list                  # hy3 listed?
hyprctl getoption general:layout     # hy3
pgrep -a conky                       # Conky running?
pgrep -a tildaz                      # TildaZ running?
hyprctl configerrors                 # empty = OK
```

Pitfalls:

- i3 keys dead right after login, fine after `hyprctl reload` → the hy3 line did not run or failed. Run `hyprpm reload && hyprctl reload` by hand and look at the output. After a Hyprland update run `hyprpm update` first.
- A program starts twice → it is in this file *and* in an XDG autostart entry (`~/.config/autostart/`) or a systemd user unit. Keep one.
